# Tailwind Responsive Implementation

Load this reference only when the repository uses Tailwind and installed utility syntax itself is the unresolved subject; Tailwind merely being installed is insufficient. Inspect its installed major, CSS entry point, configuration model, theme variables, content detection and existing utilities before copying syntax; current Tailwind lines differ materially.

- Reuse repository breakpoint/container tokens. Add a token only at a measured content failure and document the invariant it protects.
- Prefer base utilities plus targeted media/container variants. Do not generate separate semantic trees with `hidden` unless only one remains exposed and interactive.
- Verify that container-query utilities are present in the installed line/configuration and that an ancestor establishes the intended query container.
- Keep arbitrary values exceptional and explain why a design token cannot represent the constraint. Do not paste remembered default breakpoint values into application policy.
- Run the repository build and inspect emitted CSS, computed styles, class detection and production minification. Test zoom, text spacing, localization and SSR hydration like any other implementation.

Official source: [Tailwind responsive design](https://tailwindcss.com/docs/responsive-design).
