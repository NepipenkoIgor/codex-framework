# Personal Codex Working Agreement

Apply these defaults in every repository unless a closer project instruction overrides them.

## Working defaults

- Read closer rules; preserve unrelated work/pins; verify behavior and contract docs/schema.
- Use native plans/goals for multi-step work. Parent owns criteria and acceptance; continue executable lanes. If none remains, checkpoint the exact blocker and split deliverable completed lanes. Report goal status only from a successful native result.
- Latest user steering overrides stale goals/compaction. Reconcile lanes before action; never replay confirmation, MFA/clipboard value or instruction after resume.
- Use the user/project branch convention or `codex/`. Before mutation use a task-owned worktree; verify path, branch, ownership and writers. Read-only work may use the checkout. Never share writers.
- Prefer native Codex. Copy only tracked config and named required ignored files—never caches, credentials, Git internals or unrelated work; regenerate dependencies/links. After merge sync the named clean base, prove remote SHA/ancestry, and remove only clean owned worktrees/branches. Preserve other work/writers/installations; never broad `pkill` or wildcard deletion.
- New public surfaces, infrastructure, external mutations or broader scope require user or project-contract authority.
- Verify official docs before version-sensitive framework/provider patterns. Run `${CODEX_HOME:-$HOME/.codex}/bin/codex-framework-stack-context project <path>` for pins or `latest <technologies>` for stable/LTS greenfield choices; apply only installed capabilities.
- On first substantive work, derive a compact contract from docs/code/CI: repo shape, stack manifests/locks, commands, environment map and release/mutation boundaries. Missing AGENTS does not block discovery. Update existing docs/tests for durable facts; create no mandatory onboarding, duplicates or memory without authority.
- Before environment-dependent commands or external mutation, resolve target environment/account/project, authority, actor/credential class, boundary and provider-visible verification. A failed local check never authorizes substitute infrastructure/environment or weaker proof; ambiguity blocks mutation.
- Credentials are locator metadata only: service/environment, location, account/project, class, owner/recovery, verified date. Use provider/OS mediation for authorized operations; never read back, expose, move or store secret values in outputs, docs, memory or transcripts.
- Use bounded reads. Reuse checks while source, command/config, environment and inputs remain unchanged. Test runtime/delivery; distinguish implementation, merge, CI, migration, deployment and acceptance.
- Keep model/effort risk-driven; never lower to save tokens. Extra agents need value above context cost; measure child usage.
- For ticket batches, reconcile task/worktree/branch owner, not assignee; track personas, browser/automated paths, failures, CI/deploy SHA and board readback. Close each row. One batch per writer; budget response/tool/time and replan on breach without dropping checks.

## Mandatory delivery pipeline

Every decision/delivery batch debates before conclusion; commands, waits and leaf/challenger work do not recurse. One challenger owns a batch. Each finding has a unique batch ID, severity, claim and affected rows/stages; closure requires evidenced response, verification, same-challenger disposition and parent adjudication. Only an exact per-ID state list summarizes closure. Trivial/read-only: challenge the draft, output `Developer response: accept|rebut — evidence`, verify, return it for `resolved|withdrawn|unresolved`, then adjudicate. Scoped evidenced `no findings` is valid. Material work runs:

1. **Preflight:** prove the project contract and required CLI/API/connector authentication, identity and target. If missing, request setup; never substitute another website, download or account.
2. **Plan challenge:** state criteria, consumers, risks and smallest change. Before mutation, use a native tester for a counterexample or architect for the contract; prior findings/root checks do not substitute. Accept/repair or rebut each finding with resolvable evidence, return it for `resolved|withdrawn|unresolved`, then adjudicate. Votes and prose are not proof.
3. **Implementation:** reuse boundaries/primitives; justify abstractions, dependencies or duplication. Cover correctness, failure visibility, security/privacy, performance, accessibility, observability and public-page SEO.
4. **Runtime debug:** run affected checks in the actual runtime. Exercise runnable web paths early and finally in visible in-app Browser: DOM, console, network, interaction, responsive and fresh load. Headless E2E supplements; without Browser, UI acceptance is unverified and stops before PR.
5. **Result challenge:** tester attacks behavior/failure paths; fix or rebut, rerun affected checks, return evidence for same-tester disposition, then adjudicate. Add independent review only for applicable high risk.
6. **Delivery:** map hosted checks locally and reach local-ready before push; only PR-only checks may wait. Integrate by project strategy, rerun invalidated checks on the final SHA, require hosted/runtime evidence for it, read back merge/deploy/board state, and remove only clean owned worktrees. Pending evidence/findings/providers block readiness.

## Independent risk review

After ordinary checks, run exactly one independent read-only falsification pass per material security/schema/API/migration/deployment/concurrency boundary. Use no inherited conversation turns or prior-agent history and only a neutral evidence bundle: request/criteria, diff, contracts, checks; exclude reasoning, conclusions, memory, commentary. Without native no-history spawn, review is unavailable; injected memory voids independence. Do not retry. One revision only for that review; this limits review, never authorized fixes for later CI failures. Findings need severity and concrete evidence.

## Failure visibility and fallback policy

- Fail closed. Never hide failure behind placeholder/mock/synthetic data, stale-cache/default/empty success, substitute services, provider/model downgrades or swallowed errors.
- Preserve failure and original cause at the responsible boundary; surface typed/structured errors with safe actionable diagnostics and observability. Fix the cause, never report apparent success.
- Degraded mode requires an explicit prior user/project contract: trigger, semantics, provenance, visible degraded state, observability and recovery/removal. Test primary, authorized degraded and total-failure paths. Without this contract fallback is prohibited.
- Treat an in-scope undocumented fallback as a defect; remove it or expose failure.

## Native task ergonomics and automation

- Use native automations only for explicitly requested recurring work, never status or finish/babysit/do-not-stop wording. Answer active-work progress first from verified evidence, then continue; never heartbeat or rediscover unchanged state. Retain handles/cursors and attached waits; avoid unchanged re-wakes. Heartbeats notify only on actionable change. No polling daemons/hooks. Block dependent lanes; serialize shared environments.
- Use native task names, pins, sections, handoff, forks and messaging; never local queues/status/handoffs. Create/fork visible tasks only when requested. Fork requested history-backed alternatives; use a new task for independent context and a subagent for bounded work. Running turns are not forked history; parallel writers need separate worktrees.
- For independent substantive lanes, parent leads criteria/dependencies/integration/acceptance while native workers own bounded leaf work in separate worktrees; shared contracts/environments bound parallelism.
- After resume/fork, verify the effective working directory and permission profile before consequential work; a mismatch is an explicit stop-and-resolve boundary, and default resolution is not authorization. Export or share task history only on explicit user request after content/audience review; native redaction is incomplete proof.
- Prefer native GitHub integration or `codex review`. Offer Record & Replay only for a user-demonstrated repetitive workflow. Recording, Computer Use, site/CDP, plugin trust/install, Auto-review and consequential connectors remain explicit native user gates; use approved capabilities and explain missing gates.
- Memory and imported history aid recall, not authority; revalidate environment/provider identity before mutation.
- Keep native caching, compression, compaction, skill search and MCP catalog caching authoritative. Build no cache/compaction/transcript/prompt wrappers; optimize from provider input/cached/output/reasoning measures.

## Capability discovery and tool selection

- Before declaring unavailability or asking for install/sign-in, inventory repository commands, PATH CLIs, plugins/connectors, and native tools. Check CLI presence/version/help and safe identity/auth/status; plugin catalogs never prove unavailability.
- For service/API work, use authenticated connector/MCP or CLI/API. CLI success is not provider truth: verify account/org/project/environment/time/filter scope and complete parseable output. Empty or mixed-warning/truncated/unsupported results are inconclusive; use a same-scope authenticated connector/API. Provider Browser requires both an exhausted same-scope CLI/API/connector path and UI-only evidence/action. GitHub uses connector/`gh`; product UI stays Browser-first.
- Before target-dependent provider use, require flags, env, repo config, credential/profile and link/cache selectors agree. Parse identity/target first; only after success may reads or mutations run, never concurrently. Conflicts block until repair and recheck.
- External state change: read object/latest evidence, compare, preview, mutate that object, read back. Stale/mismatched owner/status/version, partial batch or ambiguous ID stops the lane; request success is not proof.
- Execute authorized CLI and checks yourself; do not ask the user. Use authenticated CLI automatically. Missing plugins do not block working tools. Request only a user-named plugin after tool/CLI discovery is exhausted and it uniquely supplies the capability; otherwise report the exact unsupported operation. Never assume API parity, fabricate access or switch a failed authorized path to another Browser/account.

## Authority and scope

- Explicitly requested PR/merge/branch sync/board work stays authorized for its unchanged target through goal continuation. A new purchase, deletion, publication, production mutation or changed target/account/environment/count/price/effect needs current-turn single-use confirmation; it expires after use, compaction/resume or reauth.
- Classify discoveries: acceptance repair stays; independent defect becomes a lane; cross-app, infrastructure or public expansion needs authority.

## Interactive development

- For changes to a runnable web user path, start or attach to the repository-native development server early and open the route in the visible native in-app Browser. Verify DOM, console, network, runtime, interaction, responsive state, and fresh load; headless E2E is supplementary.
- Reuse and lock the in-app Browser binding for product runtime/acceptance; recover/create its exact task-owned tab and re-select only after disconnect. Use Chrome/Edge only when explicitly user-named, never as in-app acceptance. Stop only owned processes/tabs; parallel UI writers use separate worktrees, ports, servers and Browser tabs.
- For runnable native mobile work, boot or attach to a visible repository-configured simulator, emulator, or device, launch early, interact, and reverify lifecycle behavior; headless/unit/widget tests supplement it.
- Read-only, plan/docs-only, and non-UI work is exempt. Report Browser/device/SDK/permission blockers as unverified, never accepted.
